# Revelio

Web app for storing and accessing short links anonymously. Create a short key for a long URL, share it, and view or manage it later with its private admin key. No account needed.

Optionally, create an account (username and password; email only for password recovery) to keep your links in one place: links created while logged in can be saved to the account, then listed, revealed and deleted from the account page.

Built with FastAPI, async SQLAlchemy (with asyncpg and PostgreSQL), Alembic, Jinja2 templates and htmx. Runs in Docker with Docker Compose.

## Requirements

- [uv](https://docs.astral.sh/uv/), which manages Python, the virtual environment and the dependencies
- [Docker](https://docs.docker.com/get-started/get-docker/) with Docker Compose, which runs PostgreSQL and the app

uv installs Python 3.12 (pinned in `.python-version`) if it's missing. Install the dependencies:

```bash
uv sync
```

This creates `.venv` and installs exactly the versions in `uv.lock`, including the development tools (pytest, Ruff, mypy).

| File | Contents |
|---|---|
| `pyproject.toml` | The dependencies: `dependencies` for the app, the `dev` group for the development tools |
| `uv.lock` | The exact version of every installed package. Generated by uv, don't edit it by hand |
| `.python-version` | The Python version |

Add a dependency with `uv add <package>` (or `uv add --dev <package>` for a development tool) and remove one with `uv remove <package>`. Both update `pyproject.toml`, `uv.lock` and `.venv`; commit the two files.

## Configuration

Copy `.env.example` to `.env` in the project root (the folder containing `pyproject.toml`) and fill in your settings:

```dotenv
ENV_NAME=local
BASE_URL=http://localhost:8000
DB_URL=postgresql+asyncpg://shortener:shortener@localhost:5432/shortener
SESSION_SECRET_KEY=<random string, see below>
```

| Variable | Meaning |
|---|---|
| `ENV_NAME` | Name of the environment, printed on startup: `local` (the default), `development`, `staging` or `production` |
| `BASE_URL` | Public address of the app, used to build the short links |
| `DB_URL` | SQLAlchemy database URL, used when the app runs on your machine. It must name an async driver: `postgresql+asyncpg://...` for PostgreSQL, or `sqlite+aiosqlite:///...` for SQLite. Docker Compose sets its own value that points to the `db` service |
| `SESSION_SECRET_KEY` | Signs the login session cookie. Anyone who knows it can forge logins, so keep it secret; changing it logs everyone out |

Generate a `SESSION_SECRET_KEY` with:

```bash
uv run python -c "import secrets; print(secrets.token_urlsafe(32))"
```

The `.env` file is not committed to git. `BASE_URL`, `DB_URL` and `SESSION_SECRET_KEY` are required: without them the app doesn't start.

## Running with Docker

From the project root:

```bash
docker compose up --build
```

This builds the image, starts PostgreSQL, applies the migrations, then starts the app at http://localhost:8000. Stop it with `Ctrl+C`.

| Service | What it does |
|---|---|
| `db` | Runs PostgreSQL and keeps its data in the `pgdata` volume |
| `migrate` | Runs `alembic upgrade head`, then exits |
| `web` | Runs the app once the migrations have finished |

`docker compose down` removes the containers and keeps the data. `docker compose down -v` also deletes the `pgdata` volume, which removes all data.

## Running locally

To run the app outside Docker, start only the database and apply the migrations. From the project root:

```bash
docker compose up -d db
```

```bash
uv run alembic upgrade head
```

Then start the app:

```bash
uv run uvicorn shortener_app.main:app --reload
```

`uv run` runs a command inside the project's `.venv`, so there's no need to activate it.

`--reload` restarts the server when you change Python files. Stop it with `Ctrl+C`. The database keeps running until you run `docker compose stop`.

Port 8000 can only be used by one app at a time, so don't run this and the `web` service together.

## Database migrations

[Alembic](https://alembic.sqlalchemy.org/) manages the database tables: the app doesn't create them on startup. Each change is a script in `migrations/versions/`.

After a change to the models, generate a migration:

```bash
uv run alembic revision --autogenerate -m "describe the change"
```

Read the generated file, because autogenerate can miss changes or get them wrong. Then apply it and commit it with the model change:

```bash
uv run alembic upgrade head
```

| Command | What it does |
|---|---|
| `uv run alembic current` | Shows which migration the database is on |
| `uv run alembic history` | Lists all migrations |
| `uv run alembic check` | Checks that the models and migrations match |
| `uv run alembic downgrade -1` | Undoes the latest migration |

## Linting and type checking

The code is formatted and linted with [Ruff](https://docs.astral.sh/ruff/) and type-checked with [mypy](https://mypy.readthedocs.io/). Both are in the `dev` dependency group, so `uv sync` installs them. Run them from the project root.

Format the code:

```bash
uv run ruff format
```

`ruff format --check` only lists files that would change, without changing them.

Lint the code:

```bash
uv run ruff check
```

`ruff check --fix` fixes the problems that can be fixed automatically, such as unused or unsorted imports.

Check the types:

```bash
uv run mypy .
```

Run the tests:

```bash
uv run pytest
```

| File | Settings |
|---|---|
| `ruff.toml` | Line length (88) and the enabled rule sets |
| `mypy.ini` | Enables the pydantic plugin, so mypy understands pydantic models |

mypy needs type hints for every library the code imports. Libraries that don't ship their own need a stub package, added with `uv add --dev`, such as `types-zxcvbn` for `zxcvbn`.

GitHub Actions runs `ruff format --check`, `ruff check`, `mypy` and `pytest` on every push (see `.github/workflows/CI.yml`), and the check fails if any of them reports a problem. It installs the dependencies with `uv sync --locked`, which also fails if `uv.lock` is out of date with `pyproject.toml`. Run `ruff format` and `ruff check --fix` before committing.

## MCP server

`shortener_app/mcp_server.py` is an [MCP](https://modelcontextprotocol.io/) server: it lets an AI client such as Claude Code create and manage links. It offers these tools:

| Tool | Input | Description |
|---|---|---|
| `create_short_link` | target URL | Creates a short link; returns the short URL and its admin key |
| `lookup_link` | key | Shows where a key points, without counting a click |
| `get_link_info` | admin key | Returns a link's details, including its clicks |
| `delete_link` | admin key | Deletes (deactivates) a link |

The server talks to the client over stdin/stdout (the stdio transport), so the code it runs must not print to stdout: use stderr or `logging` instead.

Claude Code reads `.mcp.json` and starts the server itself with `uv run python -m shortener_app.mcp_server`. Open Claude Code in the project root and approve the `revelio` server when asked. It uses the same `.env` and database as the web app, so start the database and apply the migrations first (see [Running locally](#running-locally)).

To try the tools without an AI client, use the [MCP Inspector](https://github.com/modelcontextprotocol/inspector) (needs Node.js):

```bash
npx @modelcontextprotocol/inspector uv run python -m shortener_app.mcp_server
```

Admin keys pass through the AI conversation, so anyone who can read it can manage those links.

## Endpoints

| Method | Path | Type | Description |
|---|---|---|---|
| GET | `/` | Page | Home |
| GET | `/create_url` | Page | Create a short key; logged-in users can link it to their account |
| GET | `/go` | Page | Go to a link by its key |
| GET | `/manage` | Page | View or delete a link with its admin key |
| GET | `/account` | Page | Log in / create account, or, when logged in, the account with its links |
| GET | `/{url_key}` | Redirect | Redirects to the target URL and counts the click |
| POST | `/create_url/form` | htmx fragment | Creates a short key from the form on `/create_url` |
| GET | `/go/lookup?key=…` | htmx fragment | Checks a key and shows its target URL, without counting a click |
| POST | `/manage_key/form` | htmx fragment | Shows a link's details for an admin key |
| DELETE | `/manage_key/form` | htmx fragment | Deletes (deactivates) the link for an admin key, sent as form data |
| POST | `/sign_up` | htmx form | Creates an account and logs in |
| POST | `/login` | htmx form | Logs in |
| POST | `/logout` | Form | Logs out and redirects to `/account` |
| DELETE | `/account/links/{url_key}` | htmx | Deletes (deactivates) one of the logged-in user's own links |
| POST | `/create_url` | JSON API | Creates a short key (body: `{"target_url": "..."}`) |
| GET | `/manage_key/{secret_key}` | JSON API | Returns a link's details for an admin key |
| DELETE | `/manage_key_delete/{secret_key}` | JSON API | Deletes (deactivates) a link |
| GET | `/docs` | Docs | Interactive API documentation (Swagger UI) |

Deleting is a soft delete: the link is marked inactive, so its short link and admin key stop working, but the row stays in the database.
